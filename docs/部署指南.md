# 独立部署指南

本项目是静态网站。以下是可执行的部署步骤；具体服务器的 DNS、HTTPS 与访问控制由部署环境决定。

## 1. 构建

安装 Node.js 24 和 npm 后，在项目根目录执行：

```bash
npm ci
npm run check
```

产物在 `dist/`。其中包含 HTML、打包的 JS/CSS、浏览用 WebP 和原始 PNG。`npm run preview` 仅用于本地检查，不作为生产服务。

## 2. Nginx 手动部署

将完整 `dist/` 上传至服务器上的版本目录，例如 `/var/www/visual-almanac/releases/2026-09-08/`。复制 `deploy/nginx.conf` 为站点配置，将 `root` 改为此目录，将 `server_name` 改为自己的域名。使用服务器上安装的 Nginx 执行 `nginx -t`，通过后重载配置。

域名在服务器入口配置 HTTPS。若网站用于私人浏览，可以在 Nginx 的 server 级启用 Basic Auth 或使用已有访问网关，确保 HTML、图片和数据都受保护；仅隐藏前端链接不提供权限控制。公开仓库中的内容本身已公开，站点访问控制不能将这些内容重新变为私密。

配置已区分应用路由与静态资源：详情 `/styles/british-academia` 刷新回退到 HTML；缺失的 `/images/...` 和 `/assets/...` 返回 404。HTML 和稳定路径的图片使用重新验证，带摘要的 JS/CSS 长期缓存。

## 3. Docker Compose

安装 Docker Engine 与 Compose 后执行：

```bash
docker compose up -d --build
```

容器通过 `127.0.0.1:8080` 提供服务，便于在服务器现有的 HTTPS 反向代理后运行。若要直接监听其他接口，需要明确修改端口映射与访问策略。运行时不需要 Node、数据库或额外数据卷，所有档案包含在镜像中。

```bash
docker compose logs --tail=100 web
docker compose down
```

## 4. 部署到子目录

默认部署在域名根目录。子目录示例为 `/almanac/`，构建时指定结尾带斜杠的基础路径。

PowerShell：

```powershell
$env:BASE_PATH = '/almanac/'
npm run build
Remove-Item Env:BASE_PATH
```

Linux：

```bash
BASE_PATH=/almanac/ npm run build
```

将产物放在 Nginx 文档根目录下的 `almanac/`。相应配置示例（替换实际 root）：

```nginx
server {
    listen 80;
    server_name example.com;
    root /var/www/site;
    location = /almanac { return 301 /almanac/; }
    location /almanac/assets/ {
        try_files $uri =404;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }
    location /almanac/images/ {
        try_files $uri =404;
        add_header Cache-Control "no-cache";
    }
    location /almanac/ {
        try_files $uri $uri/ /almanac/index.html;
        add_header Cache-Control "no-cache";
    }
}
```

自带 Docker 配置面向根目录；子目录需同步修改构建参数、容器复制目标和 Nginx 配置，不能只改前端 BASE_PATH。

## 5. 更新与回滚

1. 修改内容或源码，执行 `npm ci` 与 `npm run check`。
2. 将完整产物放入新的版本目录，先验证入口、筛选、详情直达、图片与复制功能。
3. 切换 Nginx root 或版本软链接并重载，不覆盖一半文件就对外提供新版本。容器部署则构建新镜像后重启服务。
4. 回滚时切回保留的旧版本目录或旧镜像。源码和原图随 Git 版本恢复。

浏览器收藏不存储在服务器上，不受内容版本回滚影响。同一域名、协议、端口下保持稳定档案 ID；换域名或从 HTTP 改 HTTPS 后，收藏不会自动迁移。

## 6. 部署验收

检查首页和详情地址直接刷新、搜索 URL、原图缩放、复制、收藏刷新、移动端和缺失资源 404。HTTPS 下验证剪贴板授权；被浏览器禁止复制时应出现可手动选择的文本。服务器部署与容器运行必须在实际目标环境验证，不能用本地构建代替。
