# 内容维护与扩展

页面不提供新增编辑操作。所有风格均使用 `src/content/styles/*.json` 中的同一结构，构建入口自动收集文件。

选题与进度统一维护在[风格分类与扩充清单](风格分类与扩充清单.md)。新增档案前核对主分类与已有内容，收录后同步更新条目状态、数据链接及各类数量。

生成新海报前，先使用[统一海报生成规范](海报生成规范.md)及[提示词母版](../templates/posters/prompt.template.md)，保持标题、主图、四色色卡和三枚标签的系列结构。

## 新增一份风格

1. 将图片加入 `public/images/originals/`，文件名使用小写英文、数字和短横线。
2. 在 `src/content/assets/manifest.json` 增加稳定资源 ID、相对路径、原始文件名、宽高和来源说明。
3. 复制 `src/content/styles/british-academia.json` 为新文件，修改档案 ID、名称、描述、图片、配色和笔记，并重新研究、撰写该风格的设计史及来源。也可从下方结构示例开始。
4. 分类来自 `categories.ts`，标签来自 `tags.ts`；需要新标签时补充字典，而不修改页面。
5. 执行 `npm run check`。图片浏览版本自动生成，构建校验会指出重复 ID、缺失图片、无效颜色或关联，以及缺失设计史、时间乱序和无效引用。

## 多图与多配色

`images` 可引用多份已登记资源，每项有自己的 caption；同一资源可被不同档案引用。`cover` 必须属于该档案图库。

```json
{
  "images": [
    { "asset": "new-style-poster", "caption": "主海报" },
    { "asset": "new-style-detail", "caption": "另一张参考图" }
  ],
  "palettes": [
    {
      "id": "main",
      "name": "主配色",
      "description": "人工整理的配色建议。",
      "colors": [
        {
          "id": "background",
          "name": "米白",
          "hex": "#E8D8C3",
          "status": "manual",
          "role": "背景"
        },
        { "id": "accent", "name": "强调色", "hex": null, "status": "pending" }
      ]
    },
    {
      "id": "dark",
      "name": "深色方案",
      "description": "独立的深色应用建议。",
      "colors": [
        { "id": "background", "name": "深蓝", "hex": "#1F3A5F", "status": "manual", "role": "背景" }
      ]
    }
  ]
}
```

此片段合并进完整档案使用。多图、多配色控件在数据超过一项时自动出现。

## 配色状态

| 值       | 意义               | 可复制                 |
| -------- | ------------------ | ---------------------- |
| verified | 海报文字标注已核对 | 是                     |
| sampled  | 图片色块近似取样   | 是，带来源说明         |
| manual   | 人工设定的设计用色 | 是                     |
| pending  | 尚未核对           | 否，可将 HEX 设为 null |

HEX 使用大写六位格式。首批近似取样来自原海报配色条中心附近小区域的 RGB 中位数，受纹理与渲染影响；不能当作海报文字 HEX 的转录。

`applications` 只承载设计应用建议。档案不收录实际项目验证或实践记录，旧 `practice` 字段已移除，加入该字段将无法通过校验。正文按纯文本显示，不渲染任意 HTML。

## 必填设计史（REFERENCE）

每份档案必须包含 `designHistory`，由通用 `components/history/DesignHistory.vue` 呈现，不需要修改详情页。

- `overview`：交代历史范围。对当代归纳的审美名称，说明其历史来源，不把它写成有统一起点的正式流派。
- `timeline`：至少三个按时间排列的发展阶段，各含 `year`、`period`、`title`、`body`、`sourceIds`。`year` 是排序用的起始年份；页面显示 `period`，允许“19 世纪”“1920—1930 年代”等不确定时间范围。
- `sources`：至少两项可追溯资料，各含唯一 `id`、标题 `title`、机构 `publisher`、HTTPS 原文链接 `url`。优先博物馆、档案馆、图书馆的馆藏与研究资料；每个阶段必须引用存在的来源，所有列出的来源都必须被引用。
- `interpretation`：说明历史脉络如何联系当前海报的视觉特征，区分历史事实与编辑提炼，不将海报配色当作时代标准。

校验只检查结构与引用关系，不能自动证明史实正确。编辑时必须打开来源核对年代与叙述，避免将 AI 生成海报当成历史证据。历史中的作品、展览与社会变化可以作为发展节点，无需加入实际项目验证记录。

## 代码扩展点

- `domain/`：查询、排序、分页、相关风格和配色输出纯函数。
- `repositories/catalog.ts`：统一只读内容接口，页面不直接依赖具体内容文件。
- `repositories/favorites.ts`：收藏读写与订阅接口；默认 localStorage，可独立替换为同步服务。
- `composables/`：URL 查询、共享收藏、剪贴板与提示状态。
- `components/`：列表卡片、筛选面板、图片查看器、配色面板等独立组件。
- `styles/tokens.css`：全局视觉变量。布局样式集中在 `main.css`。

相关风格优先采用显式 `related` 列表，再以共同标签数量补齐。同维度筛选是并集，不同维度是交集，修改规则时同步运行领域测试。

修改图片后重新生成浏览资源。生成脚本按源文件修改时间跳过未变化的图；若修改生成参数，请先清理 `public/images/generated/` 再运行 `npm run images`。此目录为可重建产物，不提交 Git。
